# Intent: ให้คนในพื้นที่รายงานจุดน้ำท่วม

> Status: agreed · Date: 2026-10-01 · grill ครบ 8 ข้อ ตรวจ spec แล้ว และตัดสิน Open questions สำหรับรอบนี้แล้ว · Spec: [docs/specs/flood-reports.md](../specs/flood-reports.md)

## Problem

ตอนนี้แอปแสดงแค่ระดับน้ำของสถานีวัดในแต่ละเขต (จาก `data/stations.json` ซึ่งเป็นข้อมูลสมมติ)
คนที่จะเดินทางผ่านเขตหนึ่งอยากรู้ว่าถนนหรือซอยไหนท่วมอยู่ตอนนี้ และลึกแค่ไหน แต่ค่าจากสถานีวัดไม่ได้บอกสภาพถนน
คนในพื้นที่เห็นน้ำท่วมกับตา แต่ยังไม่มีช่องทางบอกต่อในแอป

## Proposed outcome

คนในพื้นที่ส่งรายงานจุดน้ำท่วมได้ ระบุ เขต จุดสังเกต ความลึก (ซม.) และเวลาที่เห็น
คนที่เปิดดูเขตหนึ่งจะเห็นรายการจุดน้ำท่วมที่ยังเป็นปัจจุบัน จุดละหนึ่งรายการ ไม่ซ้ำกัน

สิ่งที่ตกลงแล้ว

- หนึ่ง **รายงาน** คือจุดน้ำท่วมหนึ่งจุด ไม่ใช่การส่งแต่ละครั้ง คนที่ส่งจุดเดิมเข้ามาจะนับเป็น **การยืนยัน** ของรายงานเดิม (Q1)
- **จุดเดิม** คือเขตเดียวกัน และจุดสังเกตเป็นข้อความเดียวกัน โดยไม่สนช่องว่าง ตัวพิมพ์เล็กใหญ่ และวิธีพิมพ์ภาษาไทยที่ให้ตัวอักษรหน้าตาเหมือนกัน ยอมให้มีรายการซ้ำเมื่อคนสะกดต่างกัน ดีกว่ารวมผิดจุด (Q2)
- การแจ้งจุดเดิมที่ **เวลาที่เห็น** ห่างจาก **การยืนยันล่าสุด** ไม่เกิน 2 ชั่วโมง (ก่อนหรือหลังก็ได้) นับเป็นการยืนยันรายงานเดิม ครบ 2 ชั่วโมงพอดียังนับ เกินแม้วินาทีเดียวเป็นรายงานใหม่ (Q3)
- เวลาของการยืนยันคือ **เวลาที่เห็น** ไม่ใช่เวลาที่ server ได้รับ การยืนยันล่าสุดคืออันที่เวลาที่เห็นใหม่ที่สุด
- เมื่อมีการยืนยัน แสดงความลึกของการยืนยันล่าสุด และเก็บความลึกของทุกการยืนยันไว้ (Q4)
- รายงาน **หมดอายุ** เมื่อการยืนยันล่าสุดเก่ากว่า 6 ชั่วโมง หมดอายุแล้วไม่แสดงแต่ยังเก็บไว้ (Q5)
- **ระดับความรุนแรง**: 1–10 ซม. = 1, 11–30 = 2, 31–50 = 3, 51 ขึ้นไป = 4 (Q6)
- ไม่เก็บเบอร์โทร ชื่อ หรือข้อมูลติดต่อผู้รายงาน (Q7)
- ถ้าจุดเดิมมีหลายรายงานที่ยังไม่หมดอายุ แสดงเฉพาะรายงานที่การยืนยันล่าสุดใหม่ที่สุด เพื่อให้แต่ละจุดขึ้นรายการเดียว
- เรียงรายงานในเขตจากรุนแรงมากไปน้อย ถ้าเท่ากันเอาอันที่การยืนยันล่าสุดใหม่กว่าขึ้นก่อน

วัดผลยังไง

- **รอบนี้ (ตอนส่งงาน):** ทุก acceptance criteria ใน spec มี test และผ่านทั้งหมด `npm test` และ `npm run lint` ผ่าน test เดิมไม่ถูกแก้ และ demo ได้ตามลำดับนี้ใน 2 นาที: ส่งรายงาน → ส่งจุดเดิมซ้ำแล้วเห็น `confirmations` เพิ่ม → เลื่อนเวลาเกิน 6 ชม. แล้วรายงานหายจากรายการ
- **ถ้าเปิดใช้จริงในอนาคต:** ในช่วงน้ำท่วม ทุกเขตที่สถานีวัดเกินเกณฑ์มีรายงานอย่างน้อย 1 รายงาน และอย่างน้อย 30% ของรายงานได้การยืนยันตั้งแต่ 2 ครั้งขึ้นไป รอบนี้ยังวัดไม่ได้ เพราะไม่มีผู้ใช้จริงและข้อมูลหายเมื่อรีสตาร์ต

## Constraints

**ความปลอดภัย** (Skill `security-baseline`)

- ตรวจข้อมูลทุกตัวที่ API handler ไม่เชื่อข้อมูลจาก client
- ความลึกเป็นจำนวนเต็มหน่วยเซนติเมตร 1–300 ห้ามใช้ทศนิยม
- จำกัด 10 คำขอต่อ IP ต่อ 10 นาที
- ห้ามเขียนข้อมูลส่วนบุคคลลง log และห้ามส่งกลับใน response เช่น เบอร์โทร ชื่อ และที่อยู่แบบละเอียด ให้ log เป็น ID แทน จุดสังเกตที่มีลักษณะเป็นเบอร์โทรจะถูกปฏิเสธ ชื่อคนและบ้านเลขที่ในจุดสังเกตตรวจด้วยระบบไม่ได้ ยอมรับเป็นความเสี่ยงที่เหลืออยู่
- ทุกอย่างที่แสดงต่อสาธารณะต้องบอกว่าเป็นข้อมูลจากผู้ใช้ ไม่ใช่ประกาศเตือนภัยทางการ

**ระบบและ repo**

- ห้ามส่งรายงานทดสอบไปที่ระบบจริง เช่น ROOP TAN JAI Flood Watch (`flood-api.rooptanjai.com`) อ่านข้อมูล (GET) ได้ แต่ห้ามส่งหรือลบรายงาน
- ตอนนี้แอปยังไม่มีฐานข้อมูลและยังไม่มี login เก็บข้อมูลในหน่วยความจำ ข้อมูลหายเมื่อรีสตาร์ต
- เก็บเวลาเป็น UTC และแสดงเป็นเวลากรุงเทพฯ
- เขตที่ใช้ได้มี 12 เขตตาม `src/districts.ts`
- repo นี้เป็นตัวอย่างเพื่อการเรียน ไม่ใช่บริการเตือนภัยจริง

**ความเสี่ยงที่ยอมรับในรอบนี้**

- คนเดียวยืนยันจุดเดิมซ้ำได้ จำนวนการยืนยันจึงไม่ใช่หลักฐานว่ามีหลายคนเห็น
- หลายคนที่ใช้ IP เดียวกันใช้โควตาร่วมกัน ผู้ใช้ IPv6 หลบ limit ได้
- รายงานที่หมดอายุไม่ถูกล้าง หน่วยความจำจะโตจนรีสตาร์ต

**งบและกฎบริษัท**

- งบ 0 บาท ไม่ใช้บริการภายนอกที่เสียเงิน ไม่เพิ่ม dependency ตอน runtime ใช้แค่ Node.js มาตรฐาน
- ไม่เรียก API ภายนอกจากโค้ดของฟีเจอร์นี้เลย ทั้ง GET และ POST
- ทุกการเปลี่ยนแปลงต้องผ่าน `npm test` และ `npm run lint`
